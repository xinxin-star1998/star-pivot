# StarPivot 代码生成使用说明

模块 Maven 坐标：`com.star.pivot:star-pivot-generator`（版本由根工程 `star-pivot-dependencies` BOM 管理）。

StarPivot 代码生成基于 **Velocity 模板** + **数据库表结构元数据**，可一键生成后端 Java 代码、MyBatis XML、前端 API 与 Vue 页面，并附带菜单 SQL。系统提供两种使用方式：

| 方式 | 入口菜单 | 适用场景 |
|------|----------|----------|
| **库内代码生成** | 系统工具 → 代码生成 | 表已在当前应用库中，配置持久化在 `gen_table` |
| **外部库代码生成** | 系统工具 → 外部库代码生成 | 连接任意 JDBC 库选表生成，支持写盘、Diff、自定义模板 |

---

## 1. 权限说明

### 1.1 库内代码生成（`/tool/gen`）

| 权限标识 | 说明 |
|----------|------|
| `tool:gen:query` | 列表查询、查看配置 |
| `tool:gen:import` | 从数据库导入表 |
| `tool:gen:add` | 创建表（执行建表 SQL 并导入） |
| `tool:gen:edit` | 编辑生成配置 |
| `tool:gen:delete` | 删除生成配置 |
| `tool:gen:sync` | 同步数据库表结构 |
| `tool:gen:preview` | 预览生成代码 |
| `tool:gen:create` | 下载 ZIP 生成代码 |

### 1.2 外部库代码生成（`/tool/gen/external`）

| 权限标识 | 说明 |
|----------|------|
| `tool:external:query` | 连接数据库、查表、路径配置 |
| `tool:external:preview` | 预览代码、写盘 Diff |
| `tool:external:create` | 下载 ZIP、写盘生成、导入 gen_table、回退写盘 |

> 若菜单中看不到对应入口，请执行 `sql/patch_external_gen_menu.sql` 或联系管理员分配权限。

## 2. 全局配置

### 2.1 默认生成参数（`generator.yml`）

```yaml
gen:
  author: xinxin                          # 默认作者（导入表时使用）
  packageName: com.star.pivot.system      # 默认 Java 包路径
  autoRemovePre: false                    # 是否自动去除表前缀
  tablePrefix: sys_                       # 表前缀，多个用逗号分隔
```

`application.yml` 中的 `gen.*` 会覆盖上述默认值（以实际部署配置为准）。

### 2.2 外部库生成扩展配置（`application.yml`）

```yaml
gen:
  external:
    enabled: true                         # 是否启用外部库生成
    session-ttl-minutes: 30               # JDBC 会话超时（分钟）
    connect-timeout-ms: 5000
    query-timeout-seconds: 30
    max-tables-per-download: 20           # 单次 ZIP 最多表数
    allowed-hosts: []                     # 连接主机白名单，空=不限
    write-to-disk-enabled: true           # 是否允许服务端写盘
    default-output-root: ''               # 写盘根目录默认值，空=user.dir
    allowed-write-paths: []               # 写盘路径白名单，空=不限（生产建议配置）
    backup-before-write: true             # 覆盖前备份到 .star-pivot-gen-backup/
    template-dir: ''                      # 自定义 Velocity 模板目录（全局）
```

## 3. 库内代码生成（推荐日常开发）

路径：**系统工具 → 代码生成**

### 3.1 典型流程

```
准备数据表 → 导入/创建表 → 编辑配置 → 预览 → 下载 ZIP → 解压合并到工程 → 执行菜单 SQL
```

#### 步骤 1：准备数据表

- **导入表**：从当前应用连接的数据库中选择已有表导入到 `gen_table`。
- **创建表**：粘贴 `CREATE TABLE` 语句，系统会先建表再自动导入（需 `tool:gen:add` 或 admin 角色）。

#### 步骤 2：编辑生成配置

点击「编辑」进入配置页，包含三个标签页：

**基本信息**

| 字段 | 说明 |
|------|------|
| 表名称 / 表描述 | 数据库表元信息 |
| 实体类名称 | Java 类名（首字母大写），如 `SysUser` |
| 作者 | 写入代码注释 |

**字段信息**

对每个字段可配置：

| 配置项 | 说明 |
|--------|------|
| Java 类型 / java 属性 | 映射到 Java 字段 |
| 插入 / 编辑 / 列表 / 查询 | 控制 CRUD 页面与接口行为 |
| 查询方式 | `EQ`、`LIKE`、`BETWEEN` 等 |
| 必填 | 表单校验 |
| 显示类型 | 文本框、下拉框、日期、图片上传、富文本等 |
| 字典类型 | 绑定系统字典，生成下拉/单选 |

**生成信息**

| 字段 | 说明 | 示例 |
|------|------|------|
| 生成模板 | `crud` 单表 / `tree` 树表 / `sub` 主子表 | `crud` |
| 前端类型 | `element-ui` / `element-plus` / `art-design-pro` | `art-design-pro` |
| 生成包路径 | Java 根包 | `com.star.pivot.system` |
| 生成模块名 | 子系统英文名 | `system` |
| 生成业务名 | 功能英文名，用于 URL、文件名 | `user` |
| 生成功能名 | 中文描述，用于菜单、注释 | `用户` |
| 上级菜单 | 生成菜单 SQL 时的父菜单 ID | 系统管理 |

**树表额外配置**（模板 = 树表时）

- 树编码字段、树父编码字段、树名称字段（如 `dept_id`、`parent_id`、`dept_name`）

**主子表额外配置**（模板 = 主子表时）

- 关联子表表名、子表外键名

#### 步骤 3：预览与生成

- **预览**：弹窗查看各文件生成内容（不落盘）。
- **生成**：下载 `starPivot.zip`（支持多选批量生成）。
- **同步**：当数据库表结构变更后，从库中重新拉取字段并保留已有业务配置。

### 3.2 ZIP 内目录结构（库内下载）

库内下载使用统一的 `vue/` 布局，便于手动拷贝：

```
main/java/com/star/pivot/{module}/          # Entity、DTO、VO、Mapper、Service、Controller
main/resources/mapper/{module}/             # Mapper XML
vue/api/{module}/{businessName}.ts|.js       # 前端 API（Vue3 为 .ts，Vue2 为 .js）
vue/views/{module}/{businessName}/           # index.vue、modules/search.vue、modules/dialog.vue
{businessName}Menu.sql                       # 菜单与按钮权限 SQL
```

> 库内下载的路径由 `GenPathProfile.forBuiltinTable()` 自动推导，无需在界面单独配置路径。

### 3.3 生成后手工步骤

1. 将 `main/java` 与 `main/resources` 合并到对应 Maven 模块（如 `star-pivot-module/star-pivot-system`）。
2. 将 `vue/api`、`vue/views` 合并到 `star-pivot-ui/src/` 对应目录。
3. 在数据库中执行 `{businessName}Menu.sql`（注意检查 `parentMenuId` 是否正确）。
4. 若为新业务模块，还需在工程中注册 Maven 模块、扫描包路径等（按项目规范操作）。
5. 重启后端、刷新前端菜单缓存后访问新页面。

## 4. 外部库代码生成

路径：**系统工具 → 外部库代码生成**

适用于：表在其他数据库、尚未导入 `gen_table`、或需要**直接写盘到项目目录**的场景。配置为**会话级**，断开连接后缓存清除（可选择导入到 `gen_table` 持久化）。

### 4.1 五步向导

| 步骤 | 内容 |
|------|------|
| ① 连接数据库 | MySQL / PostgreSQL / Oracle / SQL Server；支持连接预设（浏览器本地存储） |
| ② 选择数据表 | 模糊搜索、多选；自动过滤 `qrtz_`、`gen_` 等系统表 |
| ③ 生成模板 | 选择模板类型、前端类型；按表配置业务名、字段、树表/主子表选项 |
| ④ 路径配置 | Java 分包、Mapper XML、API、Vue 页面路径（见 4.2） |
| ⑤ 预览与下载 | 预览 / ZIP 下载 / 写盘 / 导入 gen_table |

### 4.2 路径配置说明

| 字段 | 说明 | 示例 |
|------|------|------|
| 基础包名 | Java 根包，必填 | `com.star.pivot.mall` |
| entityPackage ~ controllerPackage | 各层 Java 包 | 可点「根据基础包填充子路径」自动推导 |
| mapperXmlPath | MyBatis XML 相对路径 | `main/resources/mapper/mall` |
| apiPath | 前端 API 目录（相对项目根） | `star-pivot-ui/src/api/mall` |
| vuePagePath | 页面目录 | `star-pivot-ui/src/views/mall/brand` |
| vueModulesPath | 子组件目录 | 留空则 `{vuePagePath}/modules` |

内置预设：`system`、`mall`、`monitor`。也可保存「我的预设」到浏览器 localStorage。

### 4.3 生成范围

在预览步骤可勾选：

- **后端**（Java + XML）
- **前端**（API + Vue）
- **菜单 SQL**

### 4.4 输出方式对比

| 方式 | 说明 |
|------|------|
| **下载 ZIP** | 打包到本地，不写服务器磁盘；前端路径在 ZIP 内仍使用 `vue/` 布局 |
| **写盘生成** | 按路径配置直接写入「写盘根目录」下的工程路径；需 `write-to-disk-enabled: true` |
| **写盘 Diff 预览** | 对比磁盘与待生成内容，勾选后确认写入 |
| **回退上次写盘** | 将 `.star-pivot-gen-backup/` 中的备份写回（仅恢复被覆盖文件） |

写盘安全机制：

- `allowed-write-paths`：限制可写目录前缀
- `backup-before-write`：覆盖前自动备份
- 「写盘时跳过无变化文件」：避免无意义覆盖

### 4.5 导入代码生成

将外部库当前配置导入 `gen_table`，之后可在「库内代码生成」菜单继续维护。可选「覆盖已存在的 gen_table 配置」。

### 4.6 自定义模板目录

- **全局**：`gen.external.template-dir` 指向含 `vm/` 的目录
- **会话级**：预览步骤填写「会话模板目录」并保存，优先于全局配置
- 留空则使用 classpath 内置 `vm/` 模板

## 5. 模板类型与前端框架

### 5.1 后端模板类型

| 值 | 名称 | 生成内容 |
|----|------|----------|
| `crud` | 单表 | 标准增删改查 |
| `tree` | 树表 | 树形列表 + 父子级维护 |
| `sub` | 主子表 | 主表 + 子表 Entity/DTO/VO |

### 5.2 前端类型

| 值 | 框架 | API 模板 | 页面模板目录 |
|----|------|----------|--------------|
| `element-ui` | Vue2 + Element UI | `vm/js/api.js.vm` | `vm/vue/v2/` |
| `element-plus` | Vue3 + Element Plus | `vm/ts/api.ts.vm` | `vm/vue/v3/` |
| `art-design-pro` | Vue3 + Art Design Pro | `vm/ts/api.ts.vm` | `vm/vue/art-design-pro/` |

> Vue2（element-ui）页面为单文件 `index.vue` / `index-tree.vue`，不含 `modules` 子目录。

### 5.3 单次生成文件清单

**后端（所有模板共有）**

- `{ClassName}.java` — Entity
- `{ClassName}DTO.java`、`{ClassName}VO.java`、`{ClassName}ReqPageBo.java`（树表为 `ReqBo`）
- `{ClassName}Mapper.java` / `{ClassName}Mapper.xml`
- `I{ClassName}Service.java` / `{ClassName}ServiceImpl.java`
- `{ClassName}Controller.java`
- `{businessName}Menu.sql`

**主子表额外**

- 子表 Entity / DTO / VO

**前端（Vue3 类模板）**

- `{businessName}.ts` — API
- `index.vue` 或 `index-tree.vue`
- `modules/{businessName}-search.vue`
- `modules/{businessName}-dialog.vue`

模板源文件位于：`star-pivot-generator/src/main/resources/vm/`。

## 6. 字段自动推断规则

导入表时，系统根据列名与类型自动设置默认值（可在编辑页调整）：

| 规则 | 行为 |
|------|------|
| 主键 | 识别 `id` 或带 `@TableId` 的列 |
| 不编辑 | `id`、`create_by`、`create_time`、`del_flag` |
| 不列表 | 上述 + `update_by`、`update_time` |
| 不查询 | 上述 + `remark` |
| 字符串类型 | 默认 `String` + 文本框 |
| 数字类型 | 默认 `Long` / `Integer` 等 |
| 时间类型 | 默认 `Date` + 日期控件 |
| 文本类型 | 默认文本域 |

## 7. 常见问题

**Q：下载 ZIP 后文件应该放哪里？**

库内 ZIP 使用 `vue/` 前缀，需手动映射到 `star-pivot-ui/src/`。外部库**写盘**则按「路径配置」直接写入，无需再拷贝。

**Q：菜单 SQL 执行后页面 404？**

检查：① SQL 中 `component` 路径是否与 `vuePagePath` 一致；② 前端 `views` 下是否已有对应 `index.vue`；③ 角色是否分配新菜单权限。

**Q：同步数据库会丢失配置吗？**

同步会更新字段结构，但会尽量保留列表/查询/必填/显示类型等已有选项；数据库中已删除的列会从配置中移除。

**Q：外部库写盘提示路径不允许？**

配置 `gen.external.allowed-write-paths`，加入项目根目录或模块目录前缀，例如：

```yaml
gen:
  external:
    allowed-write-paths:
      - E:/star-pivot/project0422/StarPivot
```

**Q：如何二次开发模板？**

复制 `vm/` 目录到自定义路径，修改 Velocity 文件后配置 `gen.external.template-dir` 或会话模板目录。保持文件名与内置模板一致即可被引擎识别。

**Q：生产环境是否应开启写盘？**

建议生产关闭写盘（`write-to-disk-enabled: false`），仅使用 ZIP 下载 + 人工审核合并；并配置 `allowed-hosts`、`allowed-write-paths` 限制连接与写入范围。

## 9. 快速上手示例

以业务表 `mall_brand`（品牌管理）为例：

1. **导入表** → 表名 `mall_brand`，实体类 `MallBrand`。
2. **编辑配置** → 模板 `crud`，前端 `art-design-pro`，模块名 `mall`，业务名 `brand`，功能名 `品牌`，上级菜单选「商城管理」。
3. **字段** → 确认 `brand_name` 参与列表与查询（LIKE），`status` 绑定字典。
4. **预览** → 检查 Controller 路径与前端 API 是否符合预期。
5. **生成 ZIP** → 合并到 `star-pivot-module-mall` 与 `star-pivot-ui`。
6. **执行** `brandMenu.sql` → 分配权限 → 访问 `/mall/brand` 页面。

若表在外部库，使用「外部库代码生成」完成 ①～④ 后，在路径配置中设置 `com.star.pivot.mall` 与 `star-pivot-ui/src/views/mall/brand`，可直接「写盘 Diff 预览」确认后写入工程。
