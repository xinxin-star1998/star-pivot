# 代码生成器模板迁移指南

> 适用版本：StarPivot 当前主干（`queryDTO` → `ReqBo` / `ReqPageBo` 重构之后）

本文说明代码生成器 Velocity 模板升级后，**已生成业务代码**如何迁移，以及**重新生成**时的注意事项。

---

## 1. 变更概览

| 变更项 | 旧版 | 新版 |
|--------|------|------|
| 分页/列表查询 BO | `{ClassName}QueryDTO`（`domain/dto/`） | `{ClassName}ReqPageBo`（CRUD）或 `{ClassName}ReqBo`（树表，`domain/bo/`） |
| 分页基类 | 各 DTO 自行定义 `pageNum/pageSize` | `ReqPageBo extends PageReqBo`（framework-core） |
| 批量删除请求 | `generator.domain.bo.DeleteRequest` | `com.star.pivot.framework.domain.DeleteRequest` |
| Mapper XML 动态 SQL | 内联重复 `<if>` | `#macro(queryWhere)` 统一生成 EQ/NE/GT/LTE/LIKE/BETWEEN |
| 生成器自身查询 DTO | `GenTableQueryDTO` | **保持不变**（仅业务模板变更） |

---

## 2. 为什么要改

1. **命名统一**：与项目现有 `PageReqBo`、`LoginRequest` 等 BO 命名一致，查询入参归入 `domain.bo`。
2. **减少重复**：分页字段由 `PageReqBo` 提供，避免每个 QueryDTO 复制 `pageNum/pageSize`。
3. **Mapper 可维护**：`mapper.xml.vm` 用宏生成 where 条件，新增查询类型只改模板一处。
4. **删除请求下沉**：`DeleteRequest` 放入 framework-core，生成器与手写 Controller 共用。

---

## 3. 迁移步骤（已有生成代码）

### 3.1 查询 DTO → ReqBo

**CRUD 表（原 QueryDTO）**

1. 在 `domain/bo/` 新建 `{ClassName}ReqPageBo.java`：

```java
@Data
@EqualsAndHashCode(callSuper = true)
public class XxxReqPageBo extends PageReqBo {
    // 从原 QueryDTO 复制查询字段（不含 pageNum/pageSize）
}
```

2. 删除 `domain/dto/{ClassName}QueryDTO.java`（若仍存在）。
3. 全局替换引用：
   - `XxxQueryDTO` → `XxxReqPageBo`
   - import 路径 `domain.dto` → `domain.bo`

**树表（原 QueryDTO）**

1. 新建 `{ClassName}ReqBo.java`（不继承 `PageReqBo`）。
2. 替换 Controller / Service / Mapper 中参数名：`xxxQueryDTO` → `xxxReqBo`。

### 3.2 Controller

```java
// 旧
public Result<PageResponse<XxxVO>> list(@RequestBody XxxQueryDTO queryDTO)

// 新
public Result<PageResponse<XxxVO>> list(@Valid @RequestBody XxxReqPageBo xxxReqPageBo)
```

删除接口：

```java
// 旧
import com.star.pivot.generator.domain.bo.DeleteRequest;

// 新
import com.star.pivot.framework.domain.DeleteRequest;
```

### 3.3 Service / ServiceImpl

- 方法签名与实现中的参数类型同步替换。
- `selectXxxPage` 分页构造保持不变：`new Page<>(reqPageBo.getPageNum(), reqPageBo.getPageSize())`。

### 3.4 Mapper 接口

```java
// 旧
IPage<Xxx> selectPageList(Page<Xxx> page, @Param("query") XxxQueryDTO query);

// 新
IPage<Xxx> selectPageList(Page<Xxx> page, @Param("xxxReqPageBo") XxxReqPageBo xxxReqPageBo);
```

树表：

```java
List<Xxx> selectQueryList(@Param("xxxReqBo") XxxReqBo xxxReqBo);
```

### 3.5 Mapper XML

1. 检查 `<where>` 内 `@Param` 前缀是否与接口一致（`xxxReqPageBo.xxxField`）。
2. 若手动维护 XML，可参考新模板 `vm/xml/mapper.xml.vm` 中 `#macro(queryWhere)` 逻辑补全 NE/GTE/BETWEEN 等。
3. `BETWEEN` 查询字段命名：`begin{AttrName}` / `end{AttrName}`（如 `beginCreateTime`）。

### 3.6 前端（若已生成）

- API 请求体字段名通常与后端 BO 字段一致，**分页字段名不变**（仍 `pageNum` / `pageSize`）。
- 若 TypeScript 类型文件引用了 `QueryDTO` 命名，重命名为 `ReqPageBo` 或项目约定的 `XxxQuery` 别名即可。

## 4. 重新生成代码（覆盖策略）

| 场景 | 建议 |
|------|------|
| 全新表 | 直接使用新模板生成，无需迁移 |
| 已上线表、有手工改动 | **不要整表覆盖**；仅对照新模板 diff 合并 |
| 仅查询条件变更 | 在代码生成器 UI 调整列「查询方式」后，**只重新生成 Mapper XML + ReqBo** |
| `gen.allowOverwrite: true` | 会覆盖同名文件，生产环境保持 `false` |

生成物路径（与旧版相同）：

- Java：`main/java/{package}/...`
- XML：`main/resources/mapper/{ClassName}Mapper.xml`
- Vue：`star-pivot-ui/src/views/...`（按模板类型）

---

## 5. 生成器模块自身（无需迁移）

以下类属于**生成器内部**，未随业务模板改名：

- `GenTableQueryDTO` — 生成器列表/导入表查询
- `GenController` — 仍使用 `GenTableQueryDTO` 与 framework `DeleteRequest`

## 6. 验证清单

迁移或重新生成后，请逐项确认：

- [ ] 编译通过（`mvn -pl star-pivot-module/xxx -am compile`）
- [ ] 分页列表：条件筛选、翻页正常
- [ ] 树表：列表/展开查询正常
- [ ] 批量删除：`DeleteRequest.ids` 传递正确
- [ ] Mapper XML `@Param` 与接口、BO 字段名一致
- [ ] 前端列表页请求体字段与后端 BO 对齐

## 7. 常见问题

**Q：能否保留 QueryDTO 命名？**  
A: 可以，但不建议。与 framework 约定不一致，后续生成/Review 容易混淆。

**Q：重新生成后 ServiceImpl 被覆盖，自定义逻辑丢失？**  
A: 将自定义逻辑抽到 private 方法或独立 Helper，或关闭 `allowOverwrite` 后手工合并。

**Q：BETWEEN 查询不生效？**  
A: 检查 ReqBo 是否包含 `beginXxx` / `endXxx` 字段，以及 XML 中是否使用新宏生成的 BETWEEN 片段。
