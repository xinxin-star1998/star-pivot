# 工作流使用说明

本文档说明 StarPivot **工作流模块**的配置方式、日常使用，以及 **CRM / ERP / 商城 / 系统** 等业务模块的接入方法。

工作流采用自研 **SPF（StarPivot Flow）** JSON 模型（非 BPMN），包含流程定义、流程实例、待办任务与审批历史。

---

## 一、架构概览

```
┌──────────────────┐     发布      ┌──────────────────┐
│ 流程设计器 (UI)   │ ───────────► │ wf_process_def   │
│ defJson + 编译   │              │ runtime_json     │
└──────────────────┘              └────────┬─────────┘
                                           │
┌──────────────────┐     start     ┌──────▼─────────┐
│ 业务模块          │ ───────────► │ wf_instance    │
│ (订单/采购等)     │              │ wf_task        │
└────────┬─────────┘              └──────┬─────────┘
         │                               │ approve / reject
         │  WorkflowCompletedListener    ▼
         └◄──────────────────────  流程结束回调
```

| 概念 | 说明 |
|------|------|
| `processCode` | 流程编码，全局唯一标识一类流程，如 `mall_order_approve` |
| `businessKey` | 业务键，关联具体单据，建议 `模块:实体:ID`，如 `mall:order:10001` |
| `variables` | 流程变量 JSON，供条件分支判断（如 `amount`） |
| `instanceId` | 流程实例 ID，发起后返回，用于查进度、撤销 |
| `defJson` | 设计态 JSON（含节点坐标，供设计器/进度图渲染） |
| `runtimeJson` | 运行态 JSON（发布时编译，引擎实际执行） |

### 相关文件

| 类型 | 路径 |
|------|------|
| 后端模块 | `star-pivot-module/star-pivot-workflow/` |
| 流程引擎 | `.../service/WorkflowEngineService.java` |
| 结束回调接口 | `.../listener/WorkflowCompletedListener.java` |
| 流程定义 API | `.../controller/WfProcessDefController.java` |
| 任务/实例 API | `.../controller/WfTaskController.java` |
| 建表脚本 | `sql/workflow.sql` |
| 菜单权限 | `sql/patch_workflow_menu.sql` |
| 前端设计器 | `star-pivot-ui/src/views/workflow/designer/` |
| 前端 API | `star-pivot-ui/src/api/workflow/def.ts`、`task.ts` |
| SPF 类型 | `star-pivot-ui/src/views/workflow/utils/flow-types.ts` |

## 二、环境初始化

### 1. 执行 SQL

```bash
mysql -u root -p star-pivot < sql/workflow.sql
mysql -u root -p star-pivot < sql/patch_workflow_menu.sql
```

### 2. 模块依赖

`star-pivot-controller` 已引入 `star-pivot-workflow`，后端启动后接口前缀为 `/api/workflow/**`。

### 3. 菜单入口

| 菜单 | 路由 | 说明 |
|------|------|------|
| 工作流 → 流程定义 | `/workflow/def/index` | 列表、预览、复制、进入设计器 |
| 工作流 → 流程设计 | `/workflow/designer/index` | 设计器（通常从定义列表进入） |
| 工作流 → 待办审批 | `/workflow/approval/index` | 审批人处理待办 |
| 工作流 → 我发起的 | `/workflow/mine/index` | 发起人查看/撤销 |
| 工作流 → 流程进度 | `/workflow/flowchart/index` | 实例进度图 |

## 三、管理员：配置流程

### 1. 新建流程定义

1. 进入 **工作流 → 流程定义**
2. 点击 **新建** 或 **设计**，进入流程设计器
3. 填写 **流程编码**、**流程名称**、**业务模块**（`crm` / `erp` / `mall` / `system`）

### 2. 设计器操作

| 操作 | 说明 |
|------|------|
| 左侧拖拽 | 添加「审批」「条件」节点（开始/结束节点默认存在） |
| 连线 | 从节点**右侧蓝色圆点**拖到目标节点**左侧蓝色圆点**；或在右侧属性面板「连接到」选择目标 |
| 选中节点 | 右侧面板配置名称、审批人、审批模式 |
| 选中连线 | 右侧面板配置条件表达式（条件节点出线） |
| 自动布局 | 工具栏一键整理节点位置 |
| 模板 | 工具栏可套用「单级审批 / 两级审批 / 金额条件分支」 |
| 校验 | 保存/发布前校验连通性与节点配置 |
| 撤销/重做 | `Ctrl+Z` / `Ctrl+Y` |
| 删除 | 选中节点或连线后按 `Delete` |

### 3. 节点类型

| 类型 | 说明 |
|------|------|
| `start` | 开始节点，只能有 1 条出线，不可删除 |
| `approval` | 审批节点，需配置审批人与审批模式，只能有 1 条出线 |
| `condition` | 条件分支，最多 5 条出线，每条线可配条件或「默认分支」 |
| `end` | 结束节点，只能有 1 条入线 |

### 4. 审批人规则（assigneeRule）

| type | value | 说明 |
|------|-------|------|
| `STARTER_SELF` | — | 发起人本人 |
| `STARTER_DEPT_LEADER` | — | 发起人所在部门负责人（部门须配置 leader） |
| `ROLE` | 角色 `roleKey` | 该角色下所有启用用户 |
| `POST` | 岗位 `postCode` | 该岗位下所有启用用户 |
| `USER` | 用户 ID | 指定用户 |

**审批模式：**

- **或签（OR）**：任一人通过即进入下一节点，其余待办自动取消
- **会签（AND）**：所有审批人均通过才进入下一节点

### 5. 条件分支

条件节点每条出边上的条件格式：

```json
{
  "field": "amount",
  "op": ">",
  "value": "10000"
}
```

支持运算符：`>`、`>=`、`<`、`<=`、`==`、`!=`。数值按 `BigDecimal` 比较，非数值按字符串比较。

**必须**配置一条 **默认分支**（`{ "type": "default" }`），当所有条件不匹配时走默认分支。

发起流程时通过 `variables` 传入变量，例如：

```json
{ "amount": 12800 }
```

### 6. 保存与发布

1. **保存草稿**：写入 `wf_process_def`，状态为 `draft`
2. **发布**：编译 SPF → `runtimeJson`，状态变为 `published`
3. 只有 **已发布** 的最新版本可被业务模块 `start` 发起

> `bizModule` 仅用于流程定义分类管理，发起流程时不做强制校验。

### 7. 命名建议

```
processCode:  {bizModule}_{业务}_{动作}
              例: mall_order_approve, erp_purchase_submit

businessKey:  {bizModule}:{entity}:{id}
              例: mall:order:10001, erp:purchase:20250605001
```

## 四、日常使用（业务人员）

### 1. 发起流程

- 方式一：业务页面调用发起接口（见下文「业务模块接入」）
- 方式二：具备 `workflow:instance:start` 权限的用户，通过 API / 后续业务入口发起

发起成功后返回 `instanceId`，同一 `businessKey` 在 `RUNNING` 状态下不能重复发起。

### 2. 待办审批

进入 **工作流 → 待办审批**：

- 查看待办列表
- 点击标题或「审批」打开审批弹窗（含迷你流程图）
- **通过** / **驳回**，可填写审批意见

### 3. 我发起的

进入 **工作流 → 我发起的**：

- 查看自己发起的流程列表
- 进行中的流程可 **撤销**（仅发起人，且流程须为 `RUNNING`）
- 点击 **进度** 查看流程图与审批历史

### 4. 流程进度

- 菜单 **工作流 → 流程进度**，或业务页嵌入进度弹窗
- 接口：`GET /api/workflow/task/instance/{instanceId}/progress`
- 前端可复用组件：
  - `WorkflowProgressDialog` — 弹窗
  - `FlowProgressViewer` — 只读流程图

## 五、业务模块接入（后端）

以商城订单为例，说明其他模块如何对接。

### 1. 添加 Maven 依赖

在业务模块 `pom.xml`（如 `star-pivot-mall`）中：

```xml
<dependency>
    <groupId>com.star.pivot</groupId>
    <artifactId>star-pivot-workflow</artifactId>
</dependency>
```

### 2. 业务表建议字段

| 字段 | 说明 |
|------|------|
| `workflow_instance_id` | 流程实例 ID |
| `approve_status` | 业务审批状态（如 `DRAFT` / `PENDING` / `APPROVED` / `REJECTED`） |

### 3. 提交时发起流程

```java
@Service
@RequiredArgsConstructor
public class MallOrderService {

    private final WorkflowEngineService workflowEngineService;

    @Transactional(rollbackFor = Exception.class)
    public Long submitOrder(Long orderId) {
        MallOrder order = loadOrder(orderId);
        // 更新业务状态为审批中
        order.setApproveStatus("PENDING");

        StartWorkflowDTO dto = new StartWorkflowDTO();
        dto.setProcessCode("mall_order_approve");
        dto.setBusinessKey("mall:order:" + orderId);
        dto.setTitle("商城订单审批 #" + orderId);
        dto.setVariables(Map.of("amount", order.getTotalAmount()));

        Long instanceId = workflowEngineService.start(dto);

        order.setWorkflowInstanceId(instanceId);
        orderMapper.updateById(order);
        return instanceId;
    }
}
```

**注意：**

- `start()` 使用当前登录用户作为发起人
- 必须存在已发布的 `processCode`
- 同一 `businessKey` 不能有两个进行中的实例

### 4. 流程结束回写业务（WorkflowCompletedListener）

实现接口并注册为 Spring Bean：

```java
@Component
@RequiredArgsConstructor
public class MallOrderWorkflowListener implements WorkflowCompletedListener {

    private static final String PROCESS_CODE = "mall_order_approve";
    private final MallOrderMapper orderMapper;

    @Override
    public boolean supports(String processCode) {
        return PROCESS_CODE.equals(processCode);
    }

    @Override
    public void onApproved(String businessKey, Long instanceId) {
        Long orderId = parseId(businessKey);
        orderMapper.updateApproveStatus(orderId, "APPROVED");
    }

    @Override
    public void onRejected(String businessKey, Long instanceId, String comment) {
        Long orderId = parseId(businessKey);
        orderMapper.updateApproveStatus(orderId, "REJECTED");
    }

    private Long parseId(String businessKey) {
        return Long.parseLong(businessKey.substring(businessKey.lastIndexOf(':') + 1));
    }
}
```

引擎在 **全部审批通过** 或 **驳回** 时，自动调用所有 `supports()` 返回 `true` 的 Listener。

### 5. 撤销流程

```java
workflowEngineService.cancel(instanceId);
```

仅 **发起人** 可撤销；业务侧应同步更新单据状态。

|------|------|
| `RUNNING` | 审批进行中 |
| `APPROVED` | 审批通过 |

|------|------|
| `PENDING` | 待处理 |
| `COMPLETED` | 已处理 |
| `CANCELLED` | 已取消（或签时他人已通过、流程结束等） |

## 十一、当前能力与限制

**已支持：**

- 可视化流程设计（开始 / 审批 / 条件 / 结束）
- 或签、会签
- 多种审批人解析（本人、部门负责人、角色、岗位、指定用户）
- 条件分支（数值/字符串比较 + 默认分支）
- 待办 / 已办 / 我发起 / 进度图
- 流程结束回调（`WorkflowCompletedListener`）

**暂不支持：**

- 抄送节点
- 子流程、并行网关
- 驳回到上一节点（驳回即整单结束）
- 中间节点事件（仅流程结束时有 Listener）
- 业务模块内置示例（需按本文档自行接入）

## 十二、常见问题

### Q1：发起时报「未找到已发布的流程定义」

流程尚未发布，或 `processCode` 与定义不一致。请在 **流程定义** 中确认状态为 `published`。

### Q2：发起时报「该业务已存在进行中的流程」

同一 `businessKey` 已有 `RUNNING` 实例。需等待结束、撤销后再发起，或使用新的业务 ID。

### Q3：审批人解析失败

检查：部门是否配置 leader、角色/岗位下是否有启用用户、指定用户 ID 是否存在。

### Q4：条件分支未匹配

确认发起时 `variables` 包含条件字段；条件节点是否配置了默认分支。

### Q5：设计器有连线数据但画布不显示线

节点 Handle 使用了固定 id（`source` / `target`），渲染边时需带 `sourceHandle`、`targetHandle`，参见 `utils/flow-vue-flow.ts` 中 `toVueFlowEdge`。

## 十三、SPF 定义 JSON 结构（参考）

设计器保存的 `defJson` 核心结构：

```json
{
  "schemaVersion": "1.0",
  "processCode": "mall_order_approve",
  "processName": "商城订单审批",
  "bizModule": "mall",
  "nodes": [
    {
      "id": "start_1",
      "type": "start",
      "position": { "x": 80, "y": 200 },
      "data": { "name": "开始" }
    },
    {
      "id": "approval_1",
      "type": "approval",
      "position": { "x": 280, "y": 200 },
      "data": {
        "name": "部门负责人审批",
        "approveMode": "OR",
        "assigneeRule": { "type": "STARTER_DEPT_LEADER" }
      }
    },
    {
      "id": "end_1",
      "type": "end",
      "position": { "x": 480, "y": 200 },
      "data": { "name": "结束" }
    }
  ],
  "edges": [
    { "id": "e_1", "source": "start_1", "target": "approval_1", "data": {} },
    { "id": "e_2", "source": "approval_1", "target": "end_1", "data": {} }
  ]
}
```

发布时由 `FlowCompiler` 编译为 `runtimeJson`，业务模块 **无需** 直接操作 JSON，只需保证 `processCode` 与流程定义一致。
